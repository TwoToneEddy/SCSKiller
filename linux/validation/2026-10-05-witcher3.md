# Extraction and pre-launch compilation verification

**Result: passed for the installed Witcher 3 DX12 build on CachyOS/NVIDIA.** This verifies the original engine reading installed game files, generating pipelines without a recording, and creating those pipelines through Proton on the GPU. It does not verify game cache reuse or reduced stutter.

## Configuration

- CachyOS, NVIDIA GeForce RTX 5090, driver 615.71.09.
- Steam app 292030, build 14504303.
- Runtime selected from the game's Steam `compatdata/292030/config_info`: `/usr/share/steam/compatibilitytools.d/proton-cachyos-slr`.
- Native Qt/Python host with the original .NET core and cross-built native warmer/recorder DLL running under Proton.
- Four compiler threads, 8 GB compile memory setting, experimental generated templates enabled.
- Fresh private Proton prefix and isolated cache under `out/verification-witcher3/`. The game was not launched, the recorder was not installed, and existing Steam caches were not cleared or used as the test's output directory.
- Community database and sharing disabled for the verification. The plan contains **zero recorded pipelines and zero middleware shared items**.

## Measurements

| Operation | Result |
| --- | --- |
| Extract installed shaders | 24,266 unique shaders; 2.26 seconds for the index request |
| Read material techniques | 344,246 techniques; 40,151 distinct material pipeline combinations |
| Generate plan | 42,350 pipelines, 12 synthesized templates, 3 root signatures |
| First compile, fresh isolated disk cache | 42,350 / 42,350; 0 failures, 0 compiler skips; 119.32 seconds |
| Second helper compile, same cache | 42,350 / 42,350; 0 failures, 0 compiler skips; 5.21 seconds |
| Cache files after either pass | 275,210,233 bytes (NVIDIA driver and vkd3d output) |

Compile times include request orchestration and extraction where the original core re-indexes. They are not game launch times or frame-time measurements. The second pass launches another native compiler process. Its speedup is evidence of helper-side reuse; it does not establish that the actual game requests matching cache entries.

**Coverage limits:** the planner excluded eight stage combinations (six without a supported root signature and two involving stream output). Its 4,076 ray-tracing libraries have no generated ray-tracing state objects in this run. Those effects still require an appropriate recording. “Zero compiler skips” refers to the generated plan, not every pipeline the game could create.

## Fixes needed to reach this result

1. Initialize a private prefix with Proton `run` before using `runinprefix`; otherwise DXVK/vkd3d and ICU were missing.
2. Select native `d3d12core` as well as `d3d12`; Wine's built-in stub raised an exception during root-signature serialization.
3. Support version-3 REDengine DX12 caches and their unsuffixed filenames. Version 3 omits the two lists before the material footer; strict boundaries remain checked. Version 5 remains supported.
4. Exclude SCSKiller's staged executable from Linux game-running detection. The warmer deliberately uses `witcher3.exe` as its name and previously caused compilation to pause itself.
5. Set native Vulkan driver cache environment variables before launching Proton. Setting only the Windows child environment left the native NVIDIA driver writing to the helper cache. Each helper session now handles one game.
6. Include `x86_64-windows` translation-library paths in runtime fingerprints, so changes to those DLLs invalidate prior results. Covered by a regression test; this fingerprint-only fix was made during the run and did not change its compiler inputs.

From a built checkout, use a new output directory:

```bash
python3 linux/verify-engine.py steam:292030 \
  --output out/verification-witcher3-new --threads 4 --passes 2
```

The script refuses existing output directories and existing game recordings, and saves failures as well as successes. It performs real GPU work. No game shader bytes are included in the checked-in summary; generated binary data remains in ignored `out/`.

Remaining verification: actual game cache hits and repeatable gameplay frame times, followed by other games, GPUs and distributions. Do not generalize this result to DX11, full ray-tracing coverage, AMD, Bazzite or Flatpak Steam.
